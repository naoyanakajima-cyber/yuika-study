# チャレンジ終了時のメール通知

このフォルダーには、ブラウザー側の通知処理と、Cloudflare Workers + Resendを使う送信サーバーが入っています。**初期状態では無効で、接続設定前の結果は自動送信しません。** GitHub Pagesだけではメールを送れません。

## 通知する内容

結果画面に進んでチャレンジが終了すると、今回の教科・単元・日時・正解数／回答数と、記録されている回答・正解・解説・ヒント有無・練習モードを送ります。新しい社会と理科は個別の回答を含みます。古いクイズが記録していない選択内容やヒントは「未記録」とし、推測で補いません。暗記カードは復習完了時に初回の回答結果を送ります。自由記述の文章や過去の全履歴は送信しません。

## 保護者が最初に用意するもの

1. **Cloudflareのアカウント**：送信サーバーを置きます。
2. **Resendのアカウント**：メールを送信します。受信に使うメールアドレスで登録して確認してください。送信元はResendで利用可能なアドレスを設定します。テスト用送信元は送れる宛先に制約があるため、Resend側の案内を確認してください。本番用の独自送信元を使う場合はドメイン認証が必要です。

料金プランや契約は自動で変更しません。無料枠・送信制限は各サービスの現在の案内を確認してください。APIキー・接続キーはチャット、GitHub、HTMLに貼り付けないでください。

## 送信サーバーを配置する手順

管理者がNode.jsとCloudflareへのログインを用意し、リポジトリのルートで実行します。

```sh
npx --yes wrangler@4.151.0 login
npx --yes wrangler@4.151.0 deploy --config notifications/wrangler.jsonc
```

初回の配置直後は秘密の設定がないため送信できません。CloudflareのWorker設定画面で、次の値を**Secrets**として登録します。受信先・送信元もここだけに保持し、公開リポジトリには書きません。

| 名前 | 内容 |
| --- | --- |
| `RESEND_API_KEY` | Resendで作成したメール送信権限のAPIキー |
| `REPORT_TO` | 確認済みの保護者の完全なメールアドレス（固定宛先） |
| `REPORT_FROM` | Resendで使用を許可された送信元アドレス |
| `DEVICE_TOKEN` | パスワードマネージャーなどで生成する32文字以上のランダムな接続キー |

CLIなら `npx --yes wrangler@4.151.0 secret put RESEND_API_KEY --config notifications/wrangler.jsonc` などを使い、値は対話入力してください。コマンド引数やシェル履歴に値を書きません。

`REPORTS` Durable ObjectとSQLite移行は設定ファイルで作成します。受信先はサーバー側の `REPORT_TO` に固定し、ブラウザーが宛先を変更して送るAPIにはしていません。許可Originは既存のGitHub Pagesドメインのみです。接続キーが一致する端末からだけ受け付けます。

## iPadで一度だけ接続する

1. いつものGitHub Pagesの学習アプリをSafariで開く。
2. ページ最下部の「保護者：チャレンジ結果の自動メール」を開く。
3. 配置した `https://〜.workers.dev` のURLと `DEVICE_TOKEN` を入力する。**ResendのAPIキーではありません。**
4. 「接続を確認して有効にする」を押し、表示される送信先を確認する。
5. 5問のチャレンジを完了し、受信箱で通知を確認する。迷惑メールも確認する。

同じブラウザー・同じ保存領域を使う社会・理科で共有されます。Safariとホーム画面からの起動などで保存領域が異なる場合は、使う方で接続してください。送信設定と通常の学習記録は別キーなので、通知の停止で学習記録は消えません。

## 再送と重複の扱い

- 未送信の通知はブラウザーに保存し、起動時・オンライン復帰時・表示中に再試行します。アプリを閉じたままバックグラウンド送信する機能ではありません。
- チャレンジごとに固定の通知IDを使います。同じIDの二重送信は、ブラウザーとサーバー双方で防ぎます。
- サーバーは同時処理を直列化し、送信サービスにも同じ冪等キーを渡します。
- Resend側の冪等キーの有効期間を超える再送を避けるため、初回送信要求から23時間以上たって成否不明のものは「確認が必要」として止めます。送信済みIDは保持するので、確定済みの通知は日数がたっても再送しません。
- 成否不明時はResendの送信ログで通知ID・日時を確認します。ブラウザーの「保留通知をJSONで保全」で内容を保存できます。確認前にIDを変更して再送しないでください。
- 「送信サービスが受け付けました」は、受信箱への到着確認ではありません。到着・配信エラーはResend側と受信箱で確認します。
- 通知送信が失敗しても学習は続けられます。通知キューの保存容量も不足した場合は一時保持となるため、画面を閉じる前にJSONを保全してください。
- 自動通知の停止後は保留分も送信しません。すでに送信要求が始まっているものは取り消せません。

## 開発・検証

共通クライアントは各HTMLに埋め込み、単体HTMLとして使える構成を維持しています。変更したら再生成します。

```sh
python3 notifications/embed.py
node --test notifications/test/worker.test.mjs
python3 notifications/test/browser.py
npx --yes wrangler@4.151.0 deploy --dry-run --config notifications/wrangler.jsonc
```

ブラウザーテストはPlaywrightとChromiumが必要です。送信先APIを模擬し、実際のメールは送りません。既存アプリのCDNが環境の証明書設定で直接読み込めない場合、通常のTLS検証を行うcurlで元の資材を取得し、同じ内容をブラウザーへ渡して検証します。証明書検証を無効にはしません。

サーバーは本文を永続保存せず、通知ID・内容のハッシュ・成否・時刻・送信サービスIDを保持します。Resendには配信のために本文を送信します。ブラウザーの送信済みキューには本文を残しません。学習記録は従来どおりブラウザーに残ります。
