## 天気／日本の地形・気候

学習帳 `index.html` の理科「天気」と社会「日本の地形・気候」から開けます。各単元に基本10問＋標準5問の復習クイズと、基本用語10枚の暗記カードを追加しています。小5・中学受験向けのオリジナル問題で、特定の教材の転載ではありません。

標準問題では、気温・降水量の表の読み取り、雲や冬の雪のでき方の並べ替え、地形と気候の関係などを扱います。表は学習用の仮のデータであり、観測していない時刻の最高気温や実際の都市を断定しない解説にしています。

既存のクイズ・暗記カードと同じ記録形式を使い、単元IDは `rika-weather` と `shakai-japan-land-climate` です。問題や学習記録の既存IDは変更しません。新単元の暗記カードは、読みなどの登録した別表記も認めますが、部分一致は正解にしません。クイズは既存と同じく終了時の集計を保存し、個々の選択内容やヒントなしの正答率は記録しません。ヒントは常時表示されるため、正答率だけで習熟度を断定しないでください。

## 成績から追加練習（draft）

平安・応仁・鎌倉の単元ホームに「弱点に合わせた追加練習」を表示します。
このブラウザーの検証済み個別回答だけを分析し、直近30日・同じ論点と確認方法ごとに
各日本日の最後の回答を最大5日分比較します。誤答が2日以上あれば候補です。
同日にヒント付きで解き直した誤答も残し、ヒントなしで正解すると候補から外します。
その後のヒント付き正解だけでは再候補にせず、再誤答があれば直近5回答日で再判定します。
ヒント件数と、登録済みの取り違えペアの答えとの一致を表示しますが、原因は断定しません。
未来日時・30日より前の回答は対象外です。追加練習の日付と最終回答表示はAsia/Tokyo（日本時間）で算出します。既存記録の現地日付・offsetは変更しません。

生成は外部APIを使わない反復練習です。元問題に「復習：」を付け、正解・選択肢・読み・
解説・出典・発展区分を維持します。新しい史実や教材の根拠は生成しません。
1原問につき固定ID `元ID-review-v1` の1問とし、候補は最大10問。
分野・コース・確認方法と既存の出題数設定が適用されます。追加問題への回答も元論点の分析に
合算し、最後にヒントなしで正解すれば追加候補から外れます。通常問題数や既存IDは変更しません。

追加問題の定義は記録がなくても復元するため、再読込・JSON入出力で回答を維持できます。
未公開試作では保存キーを `yuika-prototype-v1:` 名前空間へ分離し、payloadのスキーマを維持します。追加IDを知らない旧版HTMLへの逆インポートには
対応しないため、新版で保管してください。個別回答のない旧クイズ集計からは推測しません。
追加練習の完了は既存の通知キューの仕組みを使います（初期無効、クラウドプレビューでは遮断）。
分析・一覧表示では通知しません。開発テストは合成記録・模擬APIのみです。

共通実装は `scripts/practice/adaptive.js`。変更時に `python scripts/practice/embed.py` を
実行して3つの単独HTMLに埋め込みます。検証は `python tests/adaptive_practice.py` と
`python tests/adaptive_daily.py` と `python tests/adaptive_quality.py`。
将来、レビュー済みテンプレートを追加して出題表現を拡張できます。ID・既存の採点契約と
出典を維持し、答えの意味が変わるときは別IDを使ってください。


日常利用の改善（#14に積むdraft）：難度は基本・標準・発展で絞り込めます。
応仁・鎌倉は既存のlevel、平安は暗記＝基本、ペア・流れ＝標準、理由＝発展という
コース単位の仮定です。新しい問題や答えは作らず、元問題の反復として扱います。
候補数と今回の出題数、誤答日数、最終回答日時、ヒント付き正解を一覧から確認できます。
保護者のノートでは全分野・全確認方法の要確認数と最後にヒントなしで正解した数、
分野・確認方法別の要確認数を表示します。回復数は直近5回答日の誤答の観測に基づくため、
全期間の累積改善数ではありません。正解しても定着とは断定せず、別日の通常練習を勧めます。
空データは通常練習への案内、破損・保存領域アクセス不可は判定休止と元データ保管の案内を表示し、
追加練習を無効にします。既存の保存保護・JSON書き出しを維持します。
平安の並べ替え・穴埋めは既存どおり採点し、自由記述は自動判定しません。
旧クイズの集計や理科の別形式の記録への対応、自由な新問生成、難度を変えた派生問題は、
個別観測・採点契約・教材根拠の追加設計が必要なため今回の対象外です。

品質レビューによる修正（#15に積むdraft）：原問と追加問題を同じ論点として初回・復習候補・
出会った問題数に集計します。イベントID・問題IDは変更せず、従来JSONは明示的に検証して取り込めます。旧キーからの自動移行はしません。
同日に一度でもヒントを使った日はヒント日数に含めます。平安のペア問題は標準です。
起動後の破損・別タブからの不正データ・保存失敗でも追加練習の分析を休止します。
読取不能の元データと一時保持の回答はそれぞれ書き出せます。容量不足などから復旧した後は
「保存を再試行」で正常保存を確認して再開します。子ども向けの説明を平易にし、難度変更後の
フォーカスを保ちます。保護者向け従来分析の日時表記は記録当時の仕様を維持します。

## 別日の定着確認・今日の5問（draft）

社会の平安・鎌倉・応仁の乱で利用できます。学習帳の「今日の5問」は前回の社会単元へ直接進み、初回は応仁の乱です。各単元にも開始ボタンがあります。前回のコース・分野・確認方法・問題数をブラウザー内に保存します。初期値5問、画面で変更可能です。

出題順は期限到来の再確認（古い期限順）、弱点の追加練習、通常問題。同じ元問題は1回だけ出し、選択した分野・確認方法を守ります。候補が少なければその件数で開始します。追加練習の難度絞り込みは弱点枠のみに適用します。

ヒントなし正解で再確認待ちへ進み、JST日付で1・3・7日後に確認します。間隔は仮案で、`scripts/practice/adaptive.js` の `REVIEW_INTERVAL_DAYS` を変更して `python scripts/practice/embed.py` で3ページに反映できます。予定どおりなら起点から1・3・7日、遅れた場合は実際の再確認日から次の差分日数（2日・4日）を空けます。期限前の正解とヒント付き正解では段階を進めず、誤答で弱点へ戻します。3段階を終えると「定着」と表示しますが、理解の保証ではありません。

再確認状態は、保存されている全回答の時系列から問題・確認方法別に再構築します。各回答当時の30日・直近5回答日による弱点判定を入口とし、いったん始まった再確認は30日を過ぎても保持します。既存JSONの読み込みも同じ方法で移行し、既存キー・ID・日時・採点・履歴の書き換えはしません。元問題と追加問題の履歴を統合し、JSONの書き出し・再取込みでも再構築できます。間隔設定を変えると既存履歴の再確認予定も再計算されます。

保護者サマリーの「今日の再確認」は期限超過を含む全分野・全確認方法の件数です。単元ホームの件数は現在の選択条件に対応します。設定は端末間同期・JSON引継ぎの対象外です。検証は合成記録とChromiumを使用し、実通知・公開・デプロイは行いません。

## 保護者確認モード（開発タスク14・draft）

保護者は各アプリのURL末尾に `?parent-check=1` を付けて同じタブで開きます
（例：`onin-review.html?parent-check=1`）。通常画面には入口を出しません。
これは誤操作防止用の専用入口で、本人認証ではありません。子どもには共有しないでください。
画面上部の「保護者確認モード（記録・通知なし）」と「通知は送信しません」を確認してください。
URLの入口パラメータは起動時に除去します。終了は上部の「終了」1タップです。

モードでは子どものlocalStorageを読み書きせず、タブ内のsessionStorageの
`yuika-parent-check-v1:` 保存領域を使います。成績・弱点・再確認・今日の5問・学習設定は
すべてここに分離され、同じタブの再読み込みや単元移動でも保存を確認できます。
終了時にモードの全記録を破棄して通常画面を再読み込みします。通常のタブ終了でも
sessionStorageの寿命に従って終了します（ブラウザーの「閉じたタブの復元」等は
セッションを復元する場合があるため、共有端末では必ず「終了」を押してください）。
別タブへモードを引き継ぐ操作はしないでください。
保存領域を起動時に確認できない場合は、安全のため通常入口からでも一時メモリの
確認モードで開きます。回答は再読込・移動で失われることを画面に表示し、
子どもの記録・通知へは切り替えません。一時モードでは安全のためURLの専用パラメータを
保持し、アプリ内の同じサイトへの移動にも引き継ぎます（通常のsessionStorageが使える
状態では除去します）。URLを手動で削除したり別の通常URLへ移動すると継続を保証できません。
この状態では既存記録の削除も無効です。

通知は結果の保留登録より前、再送より前、Workerのfetch直前、接続確認より前に停止し、
画面とコンソールに通知しなかったことを表示します。通常時の保留通知もモードでは
読み込まず、変更しません。モード終了後は通常の通知動作に戻ります。

既存のノイズ記録の削除は、モード上部の「保護者：既存の子どもの記録を整理」から
日時（操作端末の現地時刻）を指定し、「削除件数を確認」→「子どもの記録を削除」→
確認ダイアログで実行します。この操作だけは**子どもの既存記録を削除**します。
先に各画面のJSONを書き出し、他の学習タブを閉じてください。
対象はこのブラウザーの全単元・旧版・試作の回答、旧学習帳のセッション・クリア・
フィードバック、理科の旧集計取り込み記録で、指定日時ちょうどを含む以降です。
日時のない旧集計・設定・未知の保存キーは保持します。削除後の分析は残った回答から
再計算されます。送信済み通知の取消や、保留通知の削除・過去のクリア最高点の復元はしません。
確認中に別タブで記録が変わった場合は再確認を求めます。
削除途中で保存に失敗した場合は、変更した記録を削除前のrawへ戻すことを試みます。
ブラウザーの保存領域は複数キーの一括更新を保証しません。復元できなかった場合は
追加削除を止めて明示し、「削除前のJSONを保全」から対象キーの原本を保存できます。
復元未確認の間は画面を閉じないでください。この保全JSONは通常の回答インポートとは
別形式であり、自動復元・通常のインポートへ直接投入するためのものではありません。

全検証：`bash scripts/check_all.sh`（合成記録・通知モックのみ）。共通実装は
`scripts/parent/runtime.js`、埋め込み更新は `python scripts/parent/embed.py`。
既存の生成スクリプトを実行した後は、最後にこの埋め込みを実行してください。
