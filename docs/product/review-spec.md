# REV-SPEC: 理由が見えるおすすめ復習

状態: PdM作成、PrM/独立レビュー通過（2026-11-09）。REV-MVPは実装着手可能。
機能実装・製品公開の完了を表さない。仕様作成・レビュー時点でコードテストは実行していない。
作成日: 2026-11-09。対応実装チケット: REV-MVP。

## 目的と最小の利用体験

学習者が、保存済みの回答から「次に何を復習するか」を一つの入口で選べ、
問題ごとに選ばれた事実上の理由を理解できるようにする。保護者も同じ理由を確認できる。
誤答原因、努力、能力、定着度を推定・断定する機能ではない。

初回は `onin-review.html` と `kamakura-review.html` の各単元内に
「おすすめ復習」を追加する。現在のコース・分野・確認方法・問題数の選択を使い、
最後の誤答、時間を置いた確認、ヒントを見た正解を一回の復習にまとめる。
既存の通常練習と四つの復習入口は維持する。

## 保存項目と解釈の境界

保存形式は `{schemaVersion:1,datasetVersion:VERSION,events:[...]}`。
各eventには `id, sessionId, questionId, unitId, version, unit, course, question,
response, expected, explanation, correct, variant, mode, hint, at, offset, day` がある。
`at` はUTCのISO時刻、`offset` は記録時のタイムゾーン差、`day` はそれに基づく現地日付。
履歴は `at`、同一時刻なら `id` の文字列順で並び、末尾を「最後の記録」とする。
これは実際の回答順を同一時刻内まで復元できるという意味ではない。

- 「初回」は問題ID・確認方法ごとの最初の**記録**。アプリ外や別端末の学習は不明。
- 再回答は同じ問題・確認方法の二件目以降。既存集計の「直後」は前の記録と同日かつ30分以内、
  「同日」は30分より後、「別日」は記録上の日付が異なること。別日と24時間経過は同義でない。
- `hint=true` はアプリでヒントを開いたこと。読んだ程度・他者からの助言・アプリ外参照は不明。
  `hint=false` はこの操作が記録されなかったこと。自力で解けた保証にはしない。
- 欠落・null・文字列のhint/correct、未知の問題ID・版・確認方法を、falseや誤答に補完しない。
  現行validatorで拒否される記録はおすすめ集計へ混ぜない。
- 既存の連続正解は同日再回答やヒントあり正解も含む。これを習得確率や長期定着の指標に転用しない。
- 回答所要時間、迷い、回答理由、画像、学習者名は新しく取得しない。

## 選定ルール

おすすめ生成時に現在時刻 `now` を一度取得し、有効な履歴と現在のフィルターから計画を作る。
問題・確認方法ごとの最後の記録を用い、以下の三つへ重複なく分類する。

| 群 | 条件 | 最小の表示理由 |
| --- | --- | --- |
| A | 最後の記録が誤答 | 「前の回答をもう一度確かめよう」 |
| B | 最後の記録が正解、かつ `now - at >= 86,400,000ms` | 「前の回答から24時間以上たったよ」 |
| C | 最後の記録が正解・ヒントあり、かつ24時間未満 | 「前はヒントを見て正解したよ」 |

各群内は最後の記録が古い順、同時刻は問題IDの文字列昇順。
A→B→Cの順に一問ずつ取り、空の群を飛ばし、問題数に達するまで繰り返す。
候補数より要求数が多い場合は候補全件で終了し、重複や未回答で水増ししない。
問題数は既存の5/10/15問、初期選択15問に従う。
これにより誤答だけに偏らず時間を置いた正解問題も混ぜる。科学的に最適な間隔・配分という主張はしない。

理由は該当する事実をすべて表示する。Aが24時間以上前ならAと経過時間の理由を表示し、
Bがヒントありなら経過時間とヒントの両方を表示する。誤答時にヒントを開いていた場合は
「前の回答はヒントあり」と表示できるが、「ヒントを見て正解」と表示しない。
表示は過去の実回答本文や正解を先に見せず、今回の解答の手掛かりを不用意に増やさない。

最後の記録が未来時刻の場合、24時間経過とは扱わない。誤答やヒントの事実による候補にはできるが、
経過日数を負数表示しない。タイムゾーン変更だけで24時間の条件を満たしたことにしない。
同日で正解し直した問題は、その最後の記録に応じてAから外れる。過去の誤答回数でAへ戻さない。
通常の正解直後、未回答、対象外のコース・分野・確認方法は候補にしない。

## 画面と保存の最小仕様

1. 単元ホームにおすすめ入口と候補数を表示する。候補0件なら開始を無効にし、
   「この条件で今おすすめする復習はありません。通常練習や未回答の問題も選べます」と案内する。
   「全問習得」「苦手なし」と結論づけない。
2. 開始前に実際の出題数を確認でき、開始後は各問題に「今回選んだ理由」を読める形で表示する。
   色だけで理由を区別しない。理由と元になった履歴は開始時の計画で固定し、回答後にもすり替わらない。
3. 回答入力、ヒント、採点、解説、結果、保存と中断確認は既存の経路を使う。
   全画面の作り直しや抽象化を実装条件にしない。
4. おすすめは**選定経路**として追加し、永続eventの `mode` は既存の `normal` を使う。
   セッション内だけのおすすめフラグ・理由はeventへ書かない。ホーム等で
   「おすすめ復習の回答は、記録では通常練習に含まれます」と説明する。
   既存の保存版・mode集合を保つための初期仕様であり、専用の効果測定はできない。
5. 開始や理由表示だけでは履歴を書き換えない。回答時のみ現行の正常なeventを追加する。
   再読込後は回答を復元し、現在の履歴からおすすめを再計算する。未回答の計画自体の復元は対象外。
6. `blocked` で既存履歴が読めない場合、おすすめを無効にして「記録を読み取れないため選べません」と示す。
   通常の候補0件と区別し、元データの書き出し・上書き禁止を維持する。

## 合成履歴例

以下は実回答ではない。時計を `2030-01-03T00:00:00.000Z`、offsetを0、
フィルターを全件・通常、要求を5問に固定する。
Q1〜Q6は例示用の別名で、応仁は順に `54027-01`〜`54027-06`、鎌倉は `54025-01`〜`54025-06` に対応させる。
各eventは現在の問題から正規の `validateEvent` を通して合成する。

| 問題 | 最後の記録 | 正誤 / ヒント | 判定 |
| --- | --- | --- | --- |
| Q1 | 2030-01-02T23:50:00.000Z | 誤答 / false | A |
| Q2 | 2030-01-01T00:00:00.000Z | 正解 / false | Bの先頭 |
| Q3 | 2030-01-02T23:00:00.000Z | 正解 / true | C |
| Q4 | 2030-01-01T12:00:00.000Z | 正解 / true | B、理由は経過時間とヒント |
| Q5 | 2030-01-02T23:00:00.000Z | 正解 / false | 対象外 |
| Q6 | 記録なし | 不明 | 対象外 |

期待する出題順はQ1→Q2→Q3→Q4の4問。Q4は一度だけ。
Q1へ同じ確認方法の新しい正解・ヒントなしを追加するとQ1は候補から外れる。
通常と読みの分離は読み確認に対応する応仁 `54027-12` 等で検証し、通常の誤答だけで読み確認の候補にはしない。
別の合成ケースで同日30分以内、同日30分超、日付境界越え1分の再回答を用意し、
既存分析の区別を保持する。日付境界越え1分だけではBに入らない。

## 保存と教材更新の互換性リスク

`validateEvent` は現在の教材の問題文、正答、解説、unit/courseとの一致を要求し、
保存されたcorrectを現在の `grade` で再検証する。`validate` は全eventを検証するため、
一件の不整合でも読み込み全体を拒否する。

このため問題文・解説・正答の変更、ID削除、版変更、採点や別表記・読みの変更、
選択肢の削除は旧記録を無効化し得る。KEY据置だけでは互換性を保証しない。
新しい永続modeも旧アプリのvalidatorでは拒否されるため、今回追加しない。

REV-MVPでは教材データ、grade/normalize、validator、保存KEY/版、event形式を変更しない。
元のevent値とIDを保持し、他単元・理科のキーに書き込まない。
教材追加・訂正時の不変な問題版と移行方法はCONTENT-SPECで別途定義する。
未知の記録を捨てて「移行成功」とする処理は認めない。

## 受入条件と検証

| ID | 条件・証拠 |
| --- | --- |
| R1 | 両単元で上の合成例どおりの候補数・順・理由になる。5/10/15、候補不足、0件、同時刻ID順を検証する |
| R2 | コース・分野・確認方法を守り、通常・漢字・読みの履歴を混ぜず、一回内に重複しない |
| R3 | 24時間の1ms前は時間理由なし、ちょうど24時間からあり。日付境界だけでは対象にせず、未来時刻で負数理由を出さない |
| R4 | ヒントなし正解直後は候補外。ヒントあり誤答を正解と表示せず、古い誤答後の最新正解はAから外す。開始後の理由が変わらない |
| R5 | 閲覧・開始だけでは対象の学習記録キーが変化しない。独立した通知キューの状態とは区別する。回答では妥当なnormal eventだけ増え、既存eventを保持。変更前validatorでも新規記録を読める |
| R6 | 再読込・JSON出力/再入力で履歴を保持。未知hint等の不正記録は変換・上書きせず、おすすめ不能と元データ保護を確認する |
| R7 | 768×1024でホーム→おすすめ→回答→採点→記録→再読込を両単元で検証。選定理由・実問数・主要操作が読め、横はみ出しやJS例外がない |
| R8 | 既存onin/kamakuraテストを維持して成功。既存の通常抽選、各復習、分析、他単元キー保持が壊れていない |
| R9 | ブラウザー検証は合成記録のみ、通知APIをmockまたは遮断し実POST送信を発生させない。既存CSP・通知の検証を弱めない |

最低限の変更対象は両単元HTMLのおすすめ選定・表示と、それを確かめる合成ブラウザーテスト。
既存2テストに加えて、選定・境界・旧記録保護を確認する意味のあるテストを追加する。
既存通知テスト等の追加実行範囲は実際の差分に応じてPrM/QAが決め、同じ成功試験を目的なく反復しない。

## 対象外と次の判断

個人の実回答取込み、外部同期、全教科横断集計、新問題生成、OCR、画像保存、教材訂正・履歴移行、
AIによる誤答原因診断、学習効果の保証、実通知、テーマ変更、マージ・本番公開は対象外。
この仕様は合成データだけで実装・検証でき、個人データ保管先のCEO判断を待つ必要はない。
PrMは混合選定とnormalとしての記録という範囲を確認し、独立レビュー後にREV-MVPを着手可能とする。
