# 学習データと独立したテーマ切替仕様

状態：PrM確認・Engineer技術確認・独立QAレビュー完了。THEME-SPECの文書成果であり、機能実装済みではない。

## 目的・対象・最小範囲

好きな時代を感じる見た目を自分で選べることで、毎日の復習画面を開くきっかけを増やす。
学習者が鎌倉単元の「標準」「鎌倉」を切り替え、読みづらい・気が変わったときはすぐ標準へ戻せる。
好みの推測や回答成績による自動変更はしない。

THEME-MVPは `kamakura-review.html` のみに適用する。同画面のれんしゅう・出題・結果・
保護者のノート・記録の保存を対象に、色と控えめな枠装飾だけを変更する。
鎌倉という希望と教材内容が対応し、独立したCSS変数と学習状態を持つ画面なので最初の範囲にする。
他の4画面、教材確認室、通知設定の機能・表示文言・送信処理へ拡張しない。
これは全アプリ共通テーマの完成ではない。

- 操作名称は「見た目」。選択肢は「標準」「鎌倉」、初回は標準。
- 画面内の説明は「見た目だけを変えます。問題や記録は変わりません。」程度に留める。
- 鎌倉風は藍、生成り、朱の小さなアクセントと直線的な枠で表現する。問題を武将の台詞に書き換えない。
- キャラクターの顔・作品ロゴ・私的な写真・外部画像・外部フォント・音・動く背景は追加しない。
- 特定の作品を公式に再現するものではなく、一般的な時代の雰囲気を扱う。ユーザーの嗜好を公開fixtureへ記録しない。

## コードから確認した境界

読取基点：main `d526d65fbae116f834d14ad994a27bc50ca23b62`。
製品実装時は最新mainと既存PRを再照合する。現在の検証済み製品基点候補は
`edad8065c1f2b726e61c5cf405f8d9ff6d807480`（#7）。#10と#11は未マージであり依存にしない。

| 現行要素 | 仕様上の扱い |
| --- | --- |
| `:root`のink/muted/paper/white/line/green/pale等の色変数 | テーマ属性で見た目だけ上書き可能 |
| `header`、`main#main`、`footer` | 操作は再描画されるmainの外に置く |
| `render()`、`home()`、`quiz()`、`result()` | テーマ切替から呼ばない。main.innerHTMLの作り直しを避ける |
| `go()` | runを破棄しうるためテーマ操作に使用しない |
| `result()`の`YuikaReports.enqueue` | テーマ再適用で実行しない。通知は増やさない |
| `KEY=yuika-social-540-25-v1`、`VERSION=kamakura-540-25-v1` | 変更しない。問題ID・出題・採点・記録schemaも維持 |
| `yuika-mail-config-v1`、`yuika-mail-job-v1:` | テーマ機能は読み書きしない |
| 直接指定色のhover、input、table、note、feedback、error、SVG | 変数変更後も可読性を個別確認。教材図の意味やラベルは変えない |
| `@media print` | テーマ選択にかかわらず白い紙と標準の濃い文字で印刷する |

PR #10はhome/quizの内容を変更する。新しいテーマ操作をそれらのHTML文字列に挿入せず、
main外の独立したUI・イベント・CSSに分離することで、後の統合時の衝突を小さくする。
学習・通知処理の大きなリファクタリングや共通モジュール化は今回行わない。

## 操作と状態

1. main外の常設領域（header直後等）に「見た目」グループと2つのbuttonを配置する。
   各ボタンは `type=button`、選択状態は `aria-pressed` と目に見える「選択中」表示の両方で示す。
2. 選択時は許可された値だけを受け取り、`document.documentElement.dataset.uiTheme` を更新する。
   学習DOM・入力値・選択肢・ヒント・出題順・途中回答は作り直さず、スクロール位置を強制変更しない。
   クリック後のフォーカスは押したテーマボタンに残す。学習画面へ強制移動しない。
3. 現在選択済みのボタンを押しても学習状態は変わらず、画面再描画はしない。
   同じ有効値が保存済みなら再保存不要。未知値・未保存・前回保存失敗の場合は明示クリックで保存を試せる。
4. 未回答中、入力途中、採点後、チャレンジ結果のどこでも切替可能。
   正誤、問題文、解説、ヒント、記録行は切替前後で同じ。結果画面の再通知は発生させない。
5. 標準へ戻す操作は鎌倉を選ぶ操作と同じ場所・同じ手数で行える。

## 保存と失敗時の挙動

テーマ専用キーは `yuika-ui-theme-kamakura-v1`。値はJSONではなく文字列の `standard` または
`kamakura` のみ。単元画面の見た目設定であり、問題データや学習記録、エクスポートJSONへ追加しない。
別画面はこのキーを利用しない。ログイン、サーバー保存、端末間同期は行わない。

| 条件 | 挙動 |
| --- | --- |
| キーなし | 標準表示。初期表示だけでキーを作らない |
| 値がstandard/kamakura | 保存値を初期適用 |
| 未知の文字列・旧形式・壊れた値 | 標準表示。起動時に自動削除/上書きしない。利用者の明示選択でこのキーだけ更新可 |
| getItemが例外 | 標準で起動。学習のload/saveを止めない |
| setItemが例外 | 選択した見た目はその画面内に反映し、専用statusで「この画面では変更しました。次回の表示には保存できませんでした。」と知らせる |
| 保存成功 | 次回の同一origin・同一画面起動で復元。過去のテーマ保存エラー表示を解消 |
| 標準へ戻す | standardをこのキーだけへ保存。学習キーの削除・clearは禁止 |

保存例外のメッセージにはmain外のテーマ専用 `role=status` を使い、既存 `#notice` の
学習記録の保存失敗・破損警告を上書きしない。テーマの失敗で既存学習状態のblockedフラグを変更しない。
同じ画面の再読込時に保存値を読み直す。別タブの変更の即時同期はMVP対象外で、
既存の学習記録用storageイベントを流用しない。

## 見た目・アクセシビリティ

標準の色・問題レイアウトを保ち、テーマ操作領域だけを追加する。鎌倉は
`html[data-ui-theme="kamakura"]` 以下のCSS変数/限定セレクターで上書きし、標準へ確実に戻せる構成にする。
対象外ページへ新しいグローバルCSSを読ませない。

| 用途 | 鎌倉の候補色 |
| --- | --- |
| paper / white | `#f7f2e8` / `#fffdf7` |
| ink / muted | `#243d4b` / `#52646b` |
| primary（green）/ pale | `#24566b` / `#e7eef0` |
| pink / rose | `#f2e4da` / `#9b493e` |
| line / gold | `#c1c8c5` / `#d9bd7b` |
| focus | `#9b493e`（外周リング、背景と十分離して表示） |

これは候補パレット。Engineerの標準sRGB計算では次の比を確認した。実装時にはcomputed styleの実際の組合せでも検証する。

| 組合せ | contrast比 | 用途・制約 |
| --- | --- | --- |
| ink / paper・white・pale・pink | 10.21・11.20・9.70・9.16 | 本文 |
| muted / paper・white・pale・pink | 5.55・6.08・5.27・4.98 | 小さな補足文字 |
| primary / paper・white・pale・pink | 7.19・7.88・6.83・6.45 | 文字・操作境界 |
| 白 / primary | 8.02 | 主ボタン文字 |
| rose / paper・white・pale・pink | 5.51・6.04・5.24・4.94 | エラー文字・外周focus |
| line / white | 1.67 | 装飾のみ。入力境界や選択状態をこの線だけで示さない |
| rose / primary | 1.30 | focusと主ボタンを直に接触させない |
| ink / gold | 6.24 | goldは原則装飾用。文字を載せるならinkのみ |

新テーマの入力境界はprimaryなど背景と3:1以上の色を使う。focusはoutline-offsetを3px以上設け、
隣接面をpaper/white/pale/pinkに限定して検証する（主ボタン面に直接重ねない）。
gold上のmuted/primary/roseは通常文字に必要な4.5:1を満たさないため使用しない。

新テーマと新規操作領域では、通常文字4.5:1以上、大きい文字3:1以上、操作状態やfocusの必要な識別部分3:1以上を満たす。
薄いlineは装飾用で、選択状態や入力欄境界の唯一の手がかりにしない。
正誤は既存の文言・記号でも区別し、色だけで示さない。SVGの固定色は意味を保ち、
背景を変えて文字が読めなくなる場合は図の背景を固定した明るい面として保持する。

- 新しいテーマボタンの押下領域は最低44×44 CSS px、間隔8px以上。画面幅に応じて折り返す。
- キーボードTabとEnter/Spaceで切替でき、focus輪郭を消さない。スクリーンリーダーでグループ名と状態が分かる。
- 問題文・解説・本文の既存文字サイズ/行間を縮めない。768×1024で主要操作が重ならず横スクロールを増やさない。
- テーマ独自の点滅・パララックス・自動アニメーション・音は設けない。reduced-motionでも状態が分かる。
- 印刷時はテーマ選択UIと装飾を隠し、paper/whiteを白、主要文字を標準の濃色へ戻す。
  印刷のために保存値や画面テーマをJSで書き換えない。

## 受入条件と合成検証計画

以下は次のTHEME-MVPで実行する条件であり、本仕様作成でテスト済みという意味ではない。

| ID | 受入条件・確認方法 |
| --- | --- |
| T1 | 新規contextで標準。標準→鎌倉→標準の表示・aria-pressed・選択中ラベルが一致。テーマ以外の画面内容と学習状態は同じ |
| T2 | 選択後の同一origin再読込で復元。キーなし/未知値/getItem例外は標準、起動だけではテーマキーを書かない |
| T3 | setItem例外では画面内適用と専用警告。既存学習警告を保持し、標準への復帰も可能。保存が再び成功すれば警告を消す |
| T4 | テーマ切替直前直後の全localStorageを比較し、変更可能なのはテーマキーだけ。合成の鎌倉/他単元/理科/既存セッションを保持 |
| T5 | 同一runの入力途中・選択済み・ヒント表示後・採点後・結果で切替。run id/問題ID列/index/results/入力値/採点内容を比較し不変。新規回答イベントを作らない |
| T6 | テーマ別に同じ合成入力のgrade結果が同一。問題ID/正答/解説/VERSION/保存schemaを維持。通常の回答・採点・記録・再読込が成功 |
| T7 | 結果表示後にYuikaReports.enqueueをspyへ置換して切替、呼出0。テーマ操作由来のネットワーク要求0、実POST到達0。実通知は模擬/遮断 |
| T8 | 768×1024でhome/quiz/feedback/result/parent/recordsを両テーマで目視。新規ボタン44px/8px、重なり・追加横overflowなし、キーボード・focus・長い説明を確認 |
| T9 | 実際の文字/背景とfocus/選択状態のcontrast比を測定。正誤文言が維持され、reduced-motionでも意味が変わらない |
| T10 | print mediaでテーマUI非表示、白背景・濃い文字。画面復帰後の選択と保存値は維持 |
| T11 | 別画面への往復で対象外画面の配色・記録が変わらない。既存応仁/鎌倉/cloud_previewテストと新規themeテストが成功 |

検証では通知APIを遮断したプレビューと新規ブラウザーcontextを用い、全履歴は合成する。
保存API全体を故障させる試験では既存学習側の警告が出ることは別の期待結果とし、
テーマキーだけ失敗させる試験と分ける。回答順の乱数差をテーマ差と誤認せず、
切替前後で同じrunを比較する。実機iPad/Safariを実施しなければ未検証と明記する。

## 対象外・後続判断

作品画像の取得、テーマ自動推定、回答によるテーマ解放、課金、テーマ共有、私的データ接続、
全画面共通化、学習イベント/通知/採点の変更、外部ライブラリ追加は対象外。
試作はdraft PRとしてCEOへ採用判断を返す。マージ、公開、デプロイは別途判断であり、
テーマ仕様確認をこれらの承認に読み替えない。D01/D02やPR #10/#11の採用待ちに依存せず着手可能。
