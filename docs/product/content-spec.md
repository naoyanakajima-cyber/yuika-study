# CONTENT-SPEC: 教材から確認できる問題案を作る

状態: PdM作成、PrM/独立レビュー通過（2026-11-10 JST）。CONTENT-MVPは合成試作として着手可能。
この文書は仕様であり、入力画面・OCR・問題生成・本番導入の実装完了を意味しない。
PdMはコードを読み取り調査し、実装・ブラウザーテストは実行していない。

## 目的と最初の体験

保護者が新しい学習内容を渡したとき、読み取った内容と問題案を見比べ、誤読や
未確認の正答を修正してから学習アプリへ追加できるようにする。取り込み件数より、
「何を根拠に、どこまで確認できたか」が明確であることを優先する。

まずCONTENT-MVPでは、同梱の合成テキスト・合成画像・合成転記・問題案を使う
独立した確認用試作を作る。画像から実際にOCRする機能や外部LLM呼出しは含めない。
合成テキストの問題案も用意済みの例であり、自由な文章からの自動生成能力をうたわない。
入力資料からの新規生成・実入力経路は、共通形式と確認体験を検証した後の別チケットにする。

保護者役のテスターは、合成資料を選び、読み取りの不明箇所を確認し、問題案を編集し、
形式エラーを直し、各問を確認して「確認済み問題案」を出力できる。
確認済みは学習内容の確認を意味し、アプリ導入・マージ・公開の承認ではない。
D01はチャット入力を採用済み（2026-11-10）。私的資料保管先・実接続D02は未決。
このMVPは引き続き合成試作に限定する。チャット入力の次段階は[引き継ぎ仕様](chat-intake-spec.md)を参照。

## 既存実装から分かった制約

調査基点はmain `d526d65fbae116f834d14ad994a27bc50ca23b62` を含む運用ブランチ。
`onin-review.html` と `kamakura-review.html` の QUESTIONS、VERSION/KEY、grade、
validateEvent、validate、importFile、および `heian-review.html` の対応処理を確認した。

- 現行のJSON読み込みは**回答記録**の取り込みであり、教材追加APIではない。
- 応仁・鎌倉のevent検証は現教材の問題文・正答・解説・unit/courseとの一致と再採点を要求する。
  一件の不整合でも全記録の読み込みを拒否する。KEY据置だけでは履歴互換性を保てない。
- 既存の問題形式は単元間で完全に同じではない。案JSONを既存QUESTIONSへ無条件に代入しない。
- 新規追加、旧教材の訂正、履歴の移行は別問題。CONTENT-MVPでは既存HTML・問題ID・
  保存キー・validator・採点・回答記録を変更しない。

## 状態と責任の分離

| 段階 | 保持・表示するもの | 次へ進む条件 |
| --- | --- | --- |
| 入力原本 | 合成text/image、参照用ID、表示名 | 同梱fixtureを選ぶ。実資料を取得しない |
| 読み取り | 転記本文、曖昧な原文断片、候補、不明箇所 | 不明を勝手に正答へ補完しない |
| 問題案 | 問題文・正答・解説等、出典範囲、生成した項目 | 形式検証と資料との照合ができる |
| 確認済み案 | 内容revisionと各問の明示確認 | 未解決箇所0、全問の確認条件成立 |
| アプリ導入 | 別チケットの教材変換・互換検証・draft PR | 確認済み案だけでは導入しない |

生成した問題文・解説・ヒントは原文の転記と別表示にし、原本にない説明を「資料から
読み取った」と表示しない。出典範囲は関連する根拠の所在であり、案全体の正しさを
証明するものではない。画像やテキスト内の命令文をエージェント権限・実行指示と扱わない。

## 共通案形式 v1

画像由来もテキスト由来も同じ問題案形式を使う。回答記録JSONとは別形式とする。
以下の必須キーを持ち、MVPで未定義のキーは検証エラーとして黙って取り込まない。

| 場所・項目 | 型・意味 |
| --- | --- |
| `format` | 固定文字列 `yuika-content-proposal`。回答記録JSONとの混同を防ぐ |
| `schemaVersion` | 整数1 |
| `packageId` | 案の識別子。`draft-`から始まる英小文字・数字・ハイフン、8〜80文字 |
| `revision` | 1以上の整数。内容変更ごとに1増加する |
| `source` | `{kind, sourceId, label, locator}`。kindはtext/image、sourceIdは案内で一意な参照ID |
| `source.label` / `source.locator` | 人に見せる資料名と同梱fixture名。URL取得・任意ファイル読込に使わない |
| `transcription.text` | 読み取った本文。文字列、最大10,000文字 |
| `transcription.uncertainties` | `{id, quote, candidates, resolution}`の配列。quoteは曖昧な原文断片、candidatesは文字列配列、resolutionは未解決ならnull、人が確かめた転記なら文字列 |
| `unit` | `{id, title}`。提案単元IDと表示名。既存単元への自動追加先ではない |
| `questions` | 1〜10件の案。以下の項目を持つ |
| `questions[].id` | 案内で一意な提案問題ID。`draft-`から始まる英小文字・数字・ハイフン、8〜80文字 |
| `questionVersion` | 整数1。提案する不変問題版。編集履歴のrevisionとは別 |
| `type` | `text` または `choice` |
| `prompt`, `answer` | 問題文、正答。draftでは未確定値null可。確認時は空でない文字列必須 |
| `aliases`, `readings` | 正答として許す別表記・読みの文字列配列。推定値を自動追加しない |
| `options` | choiceの選択肢配列。textは空配列 |
| `explanation`, `hint` | 解説・ヒント。draftではnull可、確認時は空でない文字列必須 |
| `sourceRefs` | 1件以上の `{sourceId, locator}`。例: `lines:1-2`、`page:1;region:0,0,600,200` |
| `generatedFields` | 生成・編集した項目名の配列。許可名はprompt/answer/aliases/readings/options/explanation/hint。転記と区別して表示する |
| `status` | `draft` / `confirmed` |
| `confirmedRevision` | draftならnull、confirmedなら現在のpackage revisionと同じ整数 |

`sourceRefs.locator`はMVPでは**表示専用の文字列**であり、自動的な座標切り抜きやURL
解決に使わない。textは行番号、imageはページと矩形を表示し、テスターが同梱資料と照合する。
`sourceId`は実際のsource.sourceIdを参照しなければならない。不明な参照は確認不可。
本文に存在しない引用や根拠を生成しない。MVPが出典の意味的一致を自動保証するわけではない。

## 形式検証と確認条件

draftの保存形式と確認可能条件を分ける。不完全な案を表示・修正することはできるが、
不完全なまま確認済みにはできない。読取不能なJSON、未知形式、必須キー欠落・型違いは現在の案を置換せずエラーにする。
内容上の不足・矛盾はdraftとして保持し、該当箇所の修正を促して確認を拒否する。

- `unit.id/title`、sourceId/label/locator、question ID/type、sourceRefsは必須。
  unit.id/sourceIdは英小文字・数字・ハイフン1〜80文字。表示名・locatorは最大200文字。
- 確認時のpromptは1〜1,000文字、answerは1〜200文字、explanationは1〜2,000文字、
  hintは1〜1,000文字。空白だけは空として扱う。alias/reading/optionは各1〜200文字。
- aliases/readingsは各最大10件。NFKCと前後空白除去後の同一配列内重複はエラー。
  必要性の分からない別表記は保護者が削除できる。許容表記を増やすと採点意味が変わると表示する。
- choiceは2〜6個の空でない、NFKCと前後空白除去後に重複しない選択肢を持つ。
  answerは選択肢の一つと完全一致する。choiceのaliases/readingsは空配列。
- textはoptionsが空配列。自由記述の意味採点は含めず、一つの短答と明示した許容表記の案に限る。
- 同一案の問題ID重複、既存の問題IDと同じID、未知type、未知sourceId、未解決の不明箇所は確認不可。
  **未解決uncertaintyが一件でもあれば、パッケージ内の全問を確認不可**とする。
- 不明箇所を解決するときは、元のquote/candidatesを残したままresolutionへ確認した文字列を記録する。
  正答だけを埋めて不明箇所を放置しても確認できない。候補の先頭を自動確定しない。
- 全問がconfirmedかつconfirmedRevisionが現在revisionと一致するときだけ「確認済み問題案」を出力できる。
  draft案の出力は別ボタン・別ファイル名・明確な未確認表示にし、導入済みと表示しない。

この形式検証は日本史・理科等の内容の真偽や教材の利用許諾を判定しない。
表示は文字列として行い、入力HTMLやscriptを実行しない。外部URLの自動取得・画像埋込・
リンク先への遷移を案の内容から自動で行わない。

## 編集・確認・取消・再読み込み

1. 初期fixtureも外部から読み込んだ案も、すべてdraft・confirmedRevision=nullで開始する。
   JSON内のconfirmedや作成者名は承認の証拠にしない。資料確認とCEOの公開承認を混同しない。
2. テスターが表示された資料・転記・正答・解説を確認し、個々の「この内容を確認した」を押す。
   形式検証の自動成功だけではconfirmedへ進めない。未解決箇所や不足項目を具体的に示す。
3. 問題一件、unit、source、transcription、出典、generatedFieldsを含む**内容の変更はすべて**
   package revisionを1増やし、全問のstatus=draft、confirmedRevision=nullにする。
   少量の案で失効漏れを避けるため、MVPは単問ごとのrevision最適化をしない。
4. 確認ボタン操作だけでは内容revisionを増やさない。入力変更後、以前の確認を自動復元しない。
5. 「取消」は試作内の現在案を破棄して選択前へ戻る。未保存内容があれば破棄確認を出す。
   既存の学習履歴や本番の問題を削除する操作ではない。
6. MVPの作業状態はメモリ内のみ。再読み込みでは未保存案が失われると明示する。
   draft/確認済み案はユーザー操作によるJSONダウンロードで保持できる。
   再入力時は内容を復元するが確認は失効する。localStorage等の既存学習キーには書き込まない。

D01の採用後も、現在のMVPの入口は同梱の合成サンプル選択とその編集に限定する。
JSON再入力はテスト用の合成案を対象とし、実資料アップロード画面・チャット接続・
個人資料の保存先は作らない。独立試作の「内容確認」は未認証の試験用操作であり、
実保護者本人の認証やCEO承認を証明しない。

## 不変ID・問題版と将来の導入

提案IDを既存IDへ上書きする処理や、自動で既存教材へマージする処理をMVPに作らない。
将来導入時は、独立した導入チケットで新規ID/問題版と対象単元・保存方式を決める。
承認済み導入後の問題版は不変とし、意味・正答・採点条件を変更するときは新IDまたは
新しい不変問題版として扱う。旧版定義と旧履歴を保持し、現行validatorを緩めて読ませない。
現行アプリには問題単位の版管理がないため、案のquestionVersionをそのままeventへ
追加する変更は別途設計・互換テストが必要である。

出題数追加だけでも、全件数・入力問題数等を確認する既存テストに影響する。
教材adapter、旧定義の保管、履歴移行、既存テスト期待値の変更はこのMVPの対象外。
古いeventを捨てたり不明項目を推測補完したりして移行成功とは扱わない。

## 合成サンプルと受入条件

合成fixtureは `docs/product/fixtures/` に置く。本文と画像はこの仕様のために作った架空の学習例で、
本人の回答・実教材・出版社の写真ではない。画像例の不鮮明語句は意図的に設けたもの。

- `synthetic-source.txt` と `synthetic-content.json`: 読める短文から短答案を確認する例。
- `synthetic-source.svg` と `synthetic-image-content.json`: 画像の不明箇所・複数候補・answer:nullを含む例。
  OCRの成功例ではなく、既に用意した合成転記を確認する例。

| ID | 受入条件・検証する結果 |
| --- | --- |
| C1 | 合成text/imageを同じ案形式で表示し、原本・転記・生成案が区別できる。画像例に自動OCR済みと表示しない |
| C2 | 画像例のanswer:nullと未解決uncertaintyで確認できない。不明解決・必須項目修正後のみ個別確認できる |
| C3 | JSON構造不正・未知形式/typeは取込拒否し現在案を保持。重複問題ID/選択肢、正答不在、未知sourceId、既存ID再利用はdraftで修正可能だが確認不可 |
| C4 | 全問確認前は確認済み出力不可。未確認案出力はdraft表示。全問確認後だけ確認済み案を出力できる |
| C5 | 問題/単元/原本参照/転記/不明解決/出典の編集でrevision増加・全確認失効。編集前の確認で出力できない |
| C6 | JSON再入力で内容は復元、外部confirmedはすべてdraftへ戻る。回答記録JSONは案として取り込まない |
| C7 | 取消と再読み込みの未保存警告を確認。元の学習記録キーを含め、localStorageへ一件も書き込まない |
| C8 | script/HTML風の合成文字列を文字として表示し実行しない。原本/locatorにURL風文字列があっても自動取得しない |
| C9 | 768×1024で資料・問題案・不足理由・確認/取消/出力が読め、横はみ出しやJS例外がない |
| C10 | 合成データのみ、新規ブラウザープロファイルで検証し、外部要求・通知POSTは0件。既存通知/CSP/採点テストを弱めない |
| C11 | 既存教材HTML・QUESTIONS・保存KEY・validator・採点・既存履歴に変更がなく、確認済み案でも学習アプリへ自動反映されない |

C1〜C11はCONTENT-MVPの実装受入条件であり、この仕様作成時に実施済みのテストではない。
仕様段階ではfixtureのJSON構文・参照先・未確認状態・合成データ性と受入条件の整合を確認する。
ブラウザーテストは試作実装後に行い、無変更の学習アプリ全試験を仕様作成だけのために反復しない。
