# CONTENT-TRY-SPEC：確認済み合成案のメモリ内試し解き

状態：cycle23の製品実装候補。PdM/PrM範囲確認済み。独立QAの結果は運用台帳・PRへ別途記録。利用者の製品採用・公開承認なし。
対象：CONTENT-TRY-SPEC。利用者が求めた改善のアイデアを具体化する文書成果。
作成基点：PR #11固定HEAD `3d2ed2f9a62673d2fb086a360ae841096f35b63e` の `content-review.html` と合成fixture、運用ブランチの `content-spec.md` / `improvement-next-step.md`。

## 1. 解決する問題と境界

保護者役のテスターが、内容を確認した問題案を実際の出題順に解き、問題文・許容表記・選択肢・ヒント・解説が意図した体験になるか確かめられるようにする。実児童の到達度測定ではなく、教材案の点検である。

基点PR #11には原本・転記・案の編集、個別確認、案JSONの保存がある。今回の候補はそこへ試し解き・採点を追加する。以下の契約の受入結果は独立QA後に別途記録し、現時点で検証済みと報告しない。既存の製品待ち3件（#10/#11/#12）の上限と追加既存draft #22を維持し、新しい製品PR・追加実装枠を作らない。

合成text/choiceの1〜10問、現在のメモリ内の案のみを対象とする。実資料・本人の回答・記録読取・OCR/LLM・実チャット接続・保存先D02・外部取得・認証・既存教材への導入は対象外。D01採用や本仕様の文書受入を製品採用・マージ・公開の承認に読み替えない。

## 2. 開始条件と案の不変性

「確認済みの案を試し解き」を明示操作した時だけ開始する。開始時に以下を再検証する。

1. `validateShape` と既存 `issues(p,i)` 相当の全条件が、全問について成立する。既知の同梱sourceのkind/sourceId/locator一致、出典参照、必須項目、ID、長さ、重複等を省略しない。
2. 未解決uncertaintyが0件。1件でも未解決なら、解けそうな問だけを抜き出して開始しない。
3. 全問が、現在の画面でテスターの個別操作により `status=confirmed` かつ `confirmedRevision=proposal.revision` になっている。JSONに書かれたconfirmedは信頼せず、既存通り再入力時に全問draftへ戻す。
4. textはoptions=[]、choiceは2〜6選択肢、answerが選択肢の一つと生文字列で完全一致、aliases/readings=[]。許容表記の意味を自動で広げない。
5. textのanswer/aliases/readingsは、各値を以下のNFKC+trimで正規化した後も1〜200 UTF-16 code unitであること。既存issuesを通っても、この試し解き専用条件を満たさなければ開始不可とし、該当表記の修正を案内する。無理に候補を切り詰めたり黙って除外しない。既存の案JSON形式・出力可否そのものは変更しない。

不成立なら確認画面に留まり、原因と該当欄への移動を示す。開始ボタンのdisabledだけに依存しない。形式成功を個別の内容確認の代用にしない。

既存のJSON入力は`file.text()`の非同期処理である。読込処理中は開始操作をUIと実行時ガードの両方で拒否する。読込開始時に取込世代と現在案の世代を捕捉し、完了時に一致を再確認する。途中の案編集・別サンプル採用・取消・新しい取込で世代が変わった古い結果は採用せず、「読み込み中に案が変わったため再入力してください」と伝える。読込中フラグは現行取込が成功/失敗/取消された時だけ解除し、古い完了で新しい取込のフラグを消さない。採用直前にもE状態と既存の破棄確認を確認し、試し解きの背後から案を差し替えない。

開始時にpackageId/revision、問題ID/questionVersion、順序・全問内容をメモリに複製する。出題順はquestionsの順で固定、抽選・並べ替え・既存の復習選定は呼ばない。試し解き中は案の編集・確認・案JSON出力を操作できない。回答入力・ヒント・採点・次へ・終了はproposal、revision、status、confirmedRevision、generatedFields、既存unsavedを変更しない。終了後に同じ案へ戻れば、それまでの確認はそのまま有効。

採点・次へ・入力・ヒントの各操作は、発火元のセッション識別子、問題ID/index、状態世代に結び付け、実行時に現在値との一致を確認する。A→G、次問への移動、終了/無効化では状態世代を進め、同一セッション内でも前問や採点前の遅延操作を無効にする。現在問内の通常の入力・ヒント表示だけでは世代を進めない。各採点・次へ操作では開始時revisionも再検証し、現在案の全確認条件と開始時内容との一致も確かめる。不整合が判明したら試し解きを停止して回答を消去し、「案が変わったため試し解きを終了しました。内容を確認してください」と伝える。古いスナップショットで採点しない。確認失効済みの案を自動再確認しない。

## 3. 採点契約

### 短答

比較関数を `N(s) = s.normalize('NFKC').trim()` とする。ECMAScriptのNFKCとtrimをそのまま用いる。採点時の比較にだけ使い、入力原文・案の値を書き換えない。

- 正答候補は `answer`、`aliases`全件、`readings`全件の和集合。すべてNを適用して、回答Nと完全一致する候補があれば正解。順序やanswer/alias/readingの一致先による点差は設けない。
- 漢字限定・読み限定モードは追加しない。「登録した答え・別表記・読みを認めます」と開始前に示す。別表記の推測追加、意味採点、部分一致、編集距離、ローマ字変換、辞書照合を行わない。
- 前後のECMAScript trim対象空白は無視する。内部空白は削除・連続圧縮しない。NFKCで全角空白が通常空白になるなど、互換正規化そのものの変換は適用する。内部の改行・タブも除去しない。
- 大小文字を同一視しない。句読点を除去しない。ひらがなとカタカナを同一視しない。NFKCに含まれる半角カタカナ→全角、合成可能な濁点等は正規化される。ゼロ幅文字を独自除去しない。
- 許容表記を増やす必要が見つかったら、終了して案を明示編集し、全問を再確認する。誤答から自動学習してaliases/readingsへ追記しない。
- 配列内重複は既存検証通りNFKC+trim基準で禁止。answerとalias、aliasとreading等の配列をまたぐ重なりは新規エラーにせず、同じ正解として扱う。JSONの配列・表記は勝手に統合しない。

文字列でない入力は入力エラーとして扱い、採点や文字列への暗黙変換を行わない。入力の文字数は既存実装と揃え、書記素やコードポイント数ではなくJavaScript `String.length`（UTF-16 code unit）で数える。生入力が200を超える場合、またはNFKC+trim後が200を超える場合は入力エラー。生入力が空、またはN後が空なら入力エラー。判定順は生の上限→N後の空/上限→候補比較。上限判定前に入力を切り詰めず、NFKCで長さが増える値にも上限を適用する。

入力エラーでは「答えを入力してください」または「200文字以内で入力してください（全角などの変換後も含む）」を示す。採点済みにせず、正答・解説を開かず、次へ進めず、入力を保持して修正可能にする。無回答を誤答として記録しない。

### 選択

選択はセッション・現在問題・options配列の整数indexに対応するoption identityで保持する。ラベルを再検索したり、文字列をNFKCで照合して選択済みと推定しない。正解は `options[selectedIndex] === answer` の生文字列完全一致。先頭を初期選択しない。選択肢の順序・表記は案のまま。未選択・非整数・範囲外・別問題/旧セッションの選択は入力エラーとして採点せず、正答を開かない。

採点結果は「登録した答えに一致しました」「登録した答えとは一致しません」とし、本人の理解度・努力・学習能力を断定しない。正答、登録別表記/読み、解説は採点後に確認できる。許容候補が一致した経路を表示するなら補足に留め、点数や習熟評価へ変換しない。

## 4. 表示と操作

開始前に「保護者役の合成案点検」「全n問」「回答は保存せず、終了・再読み込みで消える」を示す。開始後はi/n、問題文、短答入力または未選択の選択肢、ヒントを開く操作、採点、終了して確認画面へ戻る操作を表示する。

確認画面には正答が既に見えていたため、試し解きは答案を知らない状態の測定とは言えない。試し解き中は確認画面全体・原本・転記を可視表示、キーボード移動、アクセシビリティツリーから除外する。試し解き側では採点前だけ、正答として識別したanswer/aliases/readingsの一覧とexplanationを除外し、採点後は表示する。問題文・選択肢・明示操作で開くヒントに含まれる文字列を自動削除する意味ではない。CSSの色だけで隠したり、閉じたdetailsを開けば正答を見られる形にしない。ローカルJS内の正答を秘密にできるとは主張しない。

問題文は採点前から表示する。ヒントは最初は非表示で「ヒントを見る」を明示操作したときだけ表示し、当該問でヒントを見たことを画面内に示す。ヒント操作では正答・解説は開かない。ヒントや問題文そのものに答えを含む案は自動で書き換えず、親役が問題案の点検で発見・編集する。採点後は回答を固定し、その問で再入力・再採点できない。採点ボタンの連打でも一回のみ状態遷移する。

前の問題へ戻る機能・飛ばす機能は本候補に設けない。「戻る」は「終了して確認画面へ戻る」と明記し、前問やブラウザー履歴操作と混同しない。もう一度解く場合は確認画面から再開始し、全問を未回答で始める。試行中の一時記録は現在問の回答・採点・ヒント開示だけとし、次問へ移った時点で前問分を消す。最終問の採点後も結果を読め、「試し解きを終了」で消去する。累計点、履歴一覧、継続日数、弱点登録は作らない。

すべての案由来文字列は文字列として描画し、HTML/script/URLを実行・取得しない。768×1024、キーボード、フォーカス移動、状態通知で開始→入力→採点→次へ→終了が可能であることを将来QA対象とする。

## 5. 状態遷移（受入ケース）

状態：E=案の確認/編集、A(i)=第i問の未採点、G(i)=第i問の採点済み、Ø=案なし。試行状態の消去は回答文字列・選択・結果・ヒント状態・スナップショット・セッション識別子および表示DOMの消去を含む。終了後に古いイベントで復活させない。

| ID | 前提と操作 | 期待する状態・データ |
| --- | --- | --- |
| S01 | E、全条件成立→開始 | A(1)。全n問を固定。案・revision・確認は不変。未回答・ヒント非表示 |
| S02 | E、未確認/古いconfirmedRevision/未解決/形式問題→開始 | Eを保持し原因表示。部分的な開始不可。読み込んだconfirmedでも同じ |
| S03 | A(i)、入力変更またはヒント表示 | A(i)維持、入力と当該ヒント状態のみメモリ変更。案不変、解説非表示 |
| S04 | A(i)、空/上限超過/未選択→採点 | A(i)、入力エラー。入力保持。結果・正答・次へなし |
| S05 | A(i)、有効回答→採点を連打 | G(i)へ一回だけ遷移、入力固定、答え・解説表示。後着の重複操作は無効 |
| S06 | A(i)→次へ、またはG(n)→次へ | 操作不可。Aは採点が必要、最終問は終了操作を提示 |
| S07 | G(i), i<n→次へ | A(i+1)。前問の回答・結果・ヒント状態を消去。新問未回答。案不変 |
| S08 | A/G→終了して確認画面へ戻る、またはG(n)→終了 | 回答消去を明示した終了操作でEへ。試行状態を全消去。案・全確認・unsavedは開始前のまま。終了自体の二重確認は不要 |
| S09 | Eへ戻った後→案を編集 | 既存changedの契約通り内容変更ごとrevision+1、全問draft/confirmedRevision=null。再開始は全問明示再確認後。編集取消を除き旧確認を復元しない |
| S10 | A/G→再入力/サンプル切替を試みる | 試行中は利用不可。Eへ終了してから行う。EでJSON構造不正/読込失敗は旧案保持。正当な入力の採用時は既存破棄確認を維持し全問draft。取消したファイル選択/破棄確認は旧案不変 |
| S11 | E→「この案を取り消す」 | 既存mayDiscard条件で未保存案の破棄確認。拒否でE保持、了承でØ。試し解き中はこの操作不可、まずS08で終了。既存履歴には影響なし |
| S12 | A/G→再読み込み/ページ離脱 | 案を以前JSON出力してunsaved=falseでも、試行があれば消失を警告する条件に含める。実際に離脱したら復元しない。ブラウザーが警告を出せない場合にも冒頭の常設説明あり。beforeunloadキャンセルで同一文書が残れば状態保持。新文書/履歴復帰の復元時は試行を破棄し、新規文書はØ。ブラウザーのback-forward cache復帰でも過去回答を再表示しない |
| S13 | A/G中に案revision不一致、試行領域の作り直し、別セッション/前問/古い状態世代の遅延操作 | 不一致/再構築では試行を停止・消去してEへ理由表示。古いセッション/問題/状態世代の操作は無効。単なる現在問内の描画更新は同一セッションを保持し、暗黙の再開始・再採点をしない |

Eで案のJSON保管をした事実と、試し解きの消去警告条件を分離する。試行を終了しただけで、未保存の案を保存済み扱いにも未保存扱いにも変えない。

## 6. 完全に合成の採点例

以下の短答・選択の採点専用定義を使う。実装時には既存の同梱text sourceの一致と正しいsourceRefsを保ち、明示した合成例に整える。以下はfixtureファイルが完成したという報告ではない。T2/T3は教材知識ではなく文字比較の合成例。すべて他の確認必須項目を満たし、現在revisionで全問明示確認済みという前提。

- T1: answer=`氷`, aliases=[], readings=[`こおり`], options=[]。
- T2: answer=`ABC`, aliases=[`A B`], readings=[], options=[]。
- T3: answer=`ガラス`, aliases=[], readings=[], options=[]。
- C1: type=choice, options=[`東`,`西`], answer=`東`, aliases/readings=[]。

入力欄の引用符内はJSON文字列記法。`repeat`は記載回数の連結を意味し、省略文字を実入力する意味ではない。

| ID | 問題・正確な入力/選択 | 期待値と理由 |
| --- | --- | --- |
| G01 | T1: `"氷"` | 正解、answer一致 |
| G02 | T1: `"\u3000こおり\t"` | 正解、N=`こおり`、明示reading一致 |
| G03 | T1: `"コオリ"` | 不一致、かな種を変換しない |
| G04 | T1: `"こ おり"` | 不一致、内部空白を残す |
| G05 | T1: `"氷。"` | 不一致、句点を除去しない |
| G06 | T2: `"ＡＢＣ"` | 正解、NFKCでABC |
| G07 | T2: `"abc"` | 不一致、大小文字を区別 |
| G08 | T2: `"A\u3000B"` / `"A  B"` | 前者は正解（N=`A B`、alias一致）、後者は不一致（2空白を維持） |
| G09 | T3: `"ｶﾞﾗｽ"` | 正解、NFKCでガラス |
| G10 | T1: `""` / `" \t\u3000"` | いずれも入力エラー、未採点のまま |
| G11 | T1: `"x".repeat(200)` / `"x".repeat(201)` | 200は有効回答だが不一致。201は生入力上限エラー、切り詰めない |
| G12 | T1: `"㍍".repeat(51)` | 生51、Nは`メートル`を51回で204。正規化後上限エラー |
| G13 | C1: 現在問option index `0` / `1` / `null` / `2` | 順に正解、不一致、未選択エラー、範囲外エラー。値`"東"`だけを送っても選択identityとして受理しない |

追加の境界として、200 code unitで一致する合成answerには200 code unitの同じ回答が正解、前後空白を含む生201はtrim後200でもエラー、補助文字は1文字が2 code unit、を将来テストに含める。例えばanswer=`😀`.repeat(100)は生200、同じ回答は正解、`😀`.repeat(101)は202で入力エラー。これは文字数契約を検証する合成文字列であり学習教材としての推奨ではない。

## 7. 画像経路

現在の画像fixtureは原本自体が［判読不明］であり、候補`東`を真の読み取りとして確定する根拠がない。未解決のまま開始を拒否する負の受入例として使用する。候補先頭の自動確定・answerだけの補完・全問確認の迂回は不可。

成功経路は合成text/choiceだけで成立させ、新規画像の制作・fixture追加を本仕様の完了条件にしない。前段の改善文書にある「解決済み画像例を別途用意する」は将来の画像成功経路の条件として残し、今回の要件成果の必須範囲から外すスコープ調整である。将来、解決済み合成画像を追加する場合は、読める手作り原本・照合可能な転記/出典・人が確かめたresolution・必要な正答/解説/ヒントとgeneratedFieldsを揃える。元quote/candidatesを保持し、編集でrevision増加・全確認失効→全問明示再確認を行う。固定実装はsourceAssetをSAMPLESと照合するため、任意のlocatorへの変更や解決済みJSONだけでは成功用原本にならない。同梱原本・参照対応の追加は将来の明示実装範囲にし、外部画像取得や既存の判読不明原本を成功証拠にすることはない。

## 8. 保存互換性・外部作用

試行データは実行中のメモリだけに保持する。localStorage/sessionStorage、IndexedDB、Cookie、Cache Storage、Service Worker、window.name、URL/query/hash/history stateへ書かない。回答・結果・ヒント履歴を案JSONへ追加せず、エクスポート・ダウンロード・自動クリップボード・コンソール/診断ログ/分析イベントにも出さない。試行中の案出力ボタンは利用不可。終了後の既存案JSON出力は従来のschemaVersion=1の内容だけで、試行情報を含めない。
