# 教材更新と回答履歴の互換性（draft）

対象は詳細履歴を持つ社会3単元と理科47問。この未公開試作では回答・設定の保存先を `yuika-prototype-v1:` 専用名前空間へ隔離する。payloadのschemaVersion、datasetVersion、既存IDはそのまま。旧クイズ・暗記カードの集計から個別回答を復元しない。

## 未公開試作と元の回答を分ける

4ページの回答キーは `yuika-prototype-v1:` + 従来のキー。設定もその配下、学習帳の前回単元は `yuika-prototype-v1:last-daily-unit` を使う。元の回答・設定・前回単元・理科旧集計キーは読取りだけで、改名・削除・書換え・自動コピーをしない。旧キーの正常／破損と、試作の空履歴／破損を分けて表示する。過去に旧キーへ混在した追加練習履歴を修復したとは扱わない。

試作JSONは `format: yuika-review-prototype`、`formatVersion: 1`、教材版、`payload` を持つ専用包みで書き出す。旧版への投入には使わない。従来JSONの明示取込みは全イベントの項目・問題版・型・日時・採点・重複ID整合性を検証してから一括保存する。未知の包み・未知項目は全体を拒否し、入力rawをそのままダウンロードできる。元キーのrawも変換せず保管できる。社会schema1と理科schema2、理科の数値response/inputRaw/legacy、および任意のquestionVersionは変換しない。理科旧集計も明示取込みだけでrawを保管し、個別回答に変換しない。

試作は合成データ専用。実回答や写真の保存方法・公開は別のCEO判断を要する。自動コピーがないため、旧アプリの利用履歴が試作へ自動表示されないのは意図した動作。

## 問題の版と更新方法

問題ごとの版は `scripts/history/revisions.json` に定義全体を保存する。新規回答は `questionVersion` を持つ。版のない既存回答は、保存された問題文・解説・正解・属性・正誤が合う過去の定義で検証する。版がある回答は指定版だけを使う。別表記追加前の誤答を、あとから正解に書き換えない。過去の問題文・解説・日時・ヒントも維持する。読取りだけではlocalStorageを書き換えない。

- 文章訂正、解説・ヒント修正、同じ意味の別表記や読み追加：元IDを維持して版を1つ進める。問題HTMLを修正し、`python scripts/history/embed.py --record-editorial --reason '訂正内容と同じ意味である理由'` を実行する。前版を残したまま新定義を追加し、4ページに埋め込む。
- 意味・正解・選択肢・並べ替え構造・単元等の変更：新IDを使う。`python scripts/history/embed.py` で初版を登録する。元IDの定義は削除せず保存する。旧IDを出題対象から外しても旧記録は検証できる。旧IDと新IDの弱点・再確認状態は合算しない。
- 既存の別表記・読みの削除は同じIDでは禁止。正解表示の変更も保守的に新ID扱い。意味が同じかは担当者が確認し、理由を記録する。プログラムは文章の意味までは判定できない。

通常の生成は未登録の変更で失敗する。`--record-editorial` でも採点・構造の変更や既存別表記削除は拒否する。今回のPRでは教材本文・正解・別表記を追加変更していない。社会の既存追加練習ID（`-review-v1`）は元問題の各版から従来どおり構成する。

過去の版を削除・上書きしない。初版は独立した `tests/history_baseline_sha256.json` でも照合する。今後の版を含め、各版から合成履歴を作って検証する。未登録のID・版や矛盾するデータは従来どおり拒否し、読取り不能な元データを上書きしない。巨大・不正JSONなど既存の検証制限も維持する。

## 理科の接続

`yuika-review-v2.html` の詳細履歴だけを読取り専用で変換し、社会と同じ弱点抽出・再確認状態遷移を使う。変換は `answeredAt` → 分析用 `at`、`hintUsed` → 分析用 `hint`、確認方法は通常のみ。数値responseは数値、選択回答は文字列のまま。元の `numeric`、`grade`、問題・単位表示を使い、数値許容差も変更しない。旧集計 `legacy` は変換しない。

理科の復習と今日の5問は元の47問をそのまま出題し、追加問題・別解・難度を作らない。出題順は期限到来の再確認、弱点の復習、通常。元ID重複なし。単元と5/10問の設定を保存し、学習帳の入口も前回の理科へ戻れる。復習候補は最大10問。理科には漢字・読みコースや登録済み難度がないため、その絞り込みは提供しない。

弱点判定は直近30日・最後の5回答日（日本時間）のうち2日以上の誤答。ヒントなし正解で再確認待ちに進む。仮の間隔1・3・7日は #18 と同じ。期限前・ヒント付きでは進めず、誤答で弱点に戻る。30日を超えても開始済み状態は保持する。保存不能・読取不能時は弱点判定と今日の5問を停止し、通常回答の一時保全は既存の仕組みを使う。

## 変更後の必須チェック

```bash
python scripts/practice/embed.py
python scripts/practice/embed_science.py
python scripts/history/embed.py
python scripts/prototype/embed.py
bash scripts/check_all.sh
```

`embed_science.py` は `adaptive.js` から共通の弱点・再確認関数と間隔を取り込み、単独HTMLで動くよう埋め込む。共通ロジック変更時は社会・理科の両方を再生成する。

`history_compat.py` は全問題・各版・社会追加練習・確認方法・正誤について、旧版の合成履歴、版指定、文章訂正と別表記追加の模擬更新、旧正誤保持、廃止ID読取り、衝突・不正データ拒否、load/save/JSON再取込みを検証する。`science_adaptive.py` は47問すべてのJST境界、弱点・待機・定着・誤答復帰、ヒント・期限前の非進行、30日経過、数値・選択式の実画面、保存失敗復旧、設定再起動、JSONと学習帳入口を検証する。実回答や実通知は使わない。

`prototype_storage.py` は4ページの旧raw・設定不変、空の試作、JSON実ダウンロード／取込み、未知項目・衝突拒否、入力raw保全、容量不足と再試行、破損した旧／試作保存領域の分離を確認する。

iPad実機Safari、端末間の同期は対象外。ブラウザー内の設定は回答JSONに含めない。公開・マージ・デプロイはこのdraftには含まれない。
